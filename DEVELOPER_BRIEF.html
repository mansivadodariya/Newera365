PART B — CMS Audit: Breaking Issues & Missing Pieces

Overview

A full end-to-end audit was run across all 24 collections, the SiteSettings global, all 10 custom endpoints, the email layer, migrations, and build tooling. Below are the findings grouped by severity.

What passed cleanly: All 24 collections are present and registered. All Payload v2 API call signatures are correct. All async/await is correct. No unhandled promise rejections. Email layer (ZeptoMail SMTP via mailer.ts) is correctly wired. Access controls, localization, hooks, and admin component references are all correct.

1. Build-Breaking — TypeScript Errors in Maintenance Script

Issue

src/scripts/dedupe-analyst-calls.cts has 6 TypeScript errors. This script is written in CommonJS (require()) for Node native TS-stripping compatibility, but this strips the type signatures from the pg module — making generic query<T>() calls and untyped reducer params fail tsc.

LineError CodeDescription
55TS2347client.query<{symbol, copies}>() — untyped generic call on CommonJS pg import
63TS7006Reducer parameter n implicitly has type any
63TS7006Reducer parameter r implicitly has type any
64TS7006Reducer parameter n implicitly has type any
64TS7006Reducer parameter r implicitly has type any
76TS2347client.query<{n: string}>() — untyped generic call

Impact

Blocks npm run build and npm run type-check entirely. CI will fail on every push.

Fix

Add explicit types to the two reducer callbacks and cast the query result:

before.rows.reduce((n: number, r: {copies: string}) => n + Number(r.copies), 0)

And for the untyped generic calls, either cast the result with as or remove the generic and use explicit row typing after the call.

src/scripts/dedupe-analyst-calls.cts CRITICAL — Build Blocker Code Fix

2. Missing Database Column — mt5SyncEnabled

Issue

The mt5SyncEnabled field (the master MT5 on/off switch) is defined in src/globals/SiteSettings.ts:17 as a checkbox with default true. However, Migration 002 adds mt5_api_endpoint, mt5_api_key, and mt5_refresh_interval_secs to site_settings but does not add mt5SyncEnabled.

Impact

The /api/mt5/instruments endpoint reads settings.mt5SyncEnabled via payload.findGlobal(). If the column is absent, Postgres returns a 500 error on every MT5 instruments request — which also breaks the homepage markets widget.

Fix

Run this SQL against the Neon database (or add it to a new migration file 005_...):

ALTER TABLE site_settings ADD COLUMN IF NOT EXISTS "mt5SyncEnabled" boolean DEFAULT true;

FieldFileMissing FromSeverity
mt5SyncEnabled src/globals/SiteSettings.ts:17 All migration files CRITICAL — Runtime 500

4. Missing Slug Unique Index — Promotions Collection

Issue

The Promotions collection uses slugField('title') which generates a slug on every document. Migration 001 created compound (slug, locale) unique indexes for all slug-bearing collections — but Promotions was added after Migration 001 was written and was never included.

Impact

Slug uniqueness is enforced only at the application layer. Two editors publishing simultaneously can create two promotions with the same slug and locale, causing frontend routing conflicts.

Fix

Add to a new migration file or run directly against Neon:

CREATE UNIQUE INDEX IF NOT EXISTS uidx_promotions_slug_locale ON promotions (slug, locale);

CollectionMissing IndexSeverity
Promotions (promotions table) uidx_promotions_slug_locale HIGH — Data Integrity

6.2 — Token Comparison After DB Fetch Not Timing-Safe

ItemDetail
Filessrc/endpoints/index.ts:595–600 and :698–742
IssueThe safeTokenCompare() function exists and is used for the health check token, but is not applied after the DB fetch for confirmToken and unsubscribeToken. After fetching the subscriber record, the retrieved token should be re-compared using safeTokenCompare.
FixAfter the payload.find() call returns a doc, add: if (!safeTokenCompare(token, doc.confirmToken as string)) return 400 before proceeding.
SeverityMEDIUM

6.3 — Webinar Registration TOCTOU Race Condition

ItemDetail
Filesrc/endpoints/index.ts:1096–1128
IssueThe duplicate check does find() then create() — two separate DB calls with a gap between them. Under concurrent requests, two registrations for the same email + webinar can both pass the duplicate check and both succeed.
FixAdd a DB-level unique constraint on (email, webinar_id) in the webinar_registrations table and catch the constraint violation on create, returning the "already registered" response.
SeverityMEDIUM

6.4 — No TOTP Backup / Recovery Codes

ItemDetail
Filesrc/auth/totp.ts
IssueThe TOTP 2FA implementation has no backup/recovery codes. If an admin user loses their authenticator app, they are locked out. Manual recovery requires direct DB intervention.
FixGenerate 10 single-use recovery codes during 2FA setup, store as hashed values, allow them to be consumed one-time at login as an alternative to the 6-digit TOTP code.
SeverityMEDIUM — Usability / Admin Safety
